# I2C3 OLED 位姿显示

本版接入用户已确认的 **SSD1306、128×64、I2C 接口 0.96 寸 OLED**。`application/display_config.h` 已选定 `OLED_SSD1306`。地址在启动时检查常用的 0x3C/0x3D，接线按下表对应工程现有 I2C3 引脚。

工程现有 CubeMX 初始化为 I2C3、100 kHz、7 位地址，PA8=SCL、PC9=SDA、GPIO 开漏无内部上拉。本次没有修改 `.ioc` 或生成的外设初始化。

| 屏幕引脚 | 连接 |
| --- | --- |
| SCL | PA8 / I2C3_SCL |
| SDA | PC9 / I2C3_SDA |
| GND | STM32 GND，共地 |
| VCC | 支持 3.3 V 供电的模块接 3.3 V，按实际模块规格确认 |

I2C 需要 SCL/SDA 上拉到 3.3 V。常见模块已有上拉电阻；如果模块没有，需要外部上拉，常用 4.7 kΩ。使用当前 100 kHz 配置即可，不需要开启 I2C3 中断或 DMA。

## 显示内容

画面分四行，采用自有 **8×16 等宽点阵字体**，每行 16 个字符。有效字形为 7×12 像素，上下留白，直接绘制，不再竖向拉伸。标签占 4 列、数值占 8 列并右对齐：

```text
ODOM RUN E0
X:     123.4 MM
Y:     -56.7 MM
YAW:    12.3 DEG
```

X/Y 为底盘中心相对初始原点的坐标，单位毫米；Yaw 为相对初始朝向的航向，单位度，逆时针为正。显示一位小数是界面格式，不代表实际定位精度。数值（包含负号和小数点）超过 8 个字符时显示 `RANGE`，避免截断后读错。串口输出仍按原协议保留三位小数。

启动/同步等待显示 `WAIT`，跟踪丢失显示 `LOST`，配置等严重定位错误显示 `ERROR`，`E` 后数字对应 `g_odometry.error`。里程计读取接口判定无效时，三个数值显示 `--`，不把历史坐标显示成新定位结果。

默认刷新周期 500 ms（标称 2 Hz），由 Low 优先级独立任务执行。OLED 显示的是读取快照时的状态，完成整帧存在总线与调度延迟，不用于主控实时控制；屏幕失联时还可能保留最后画面，应以串口有效标志和断流判断为准。

## 分层与总线占用

- `bsp/bsp_oled.*` 绑定 I2C3，轮询传输，每块最多 32 字节；不屏蔽中断，采样任务可以抢占。
- `modules/oled/oled.*` 提供控制器命令、8×16 等宽字体、1 KB 静态帧缓存和分页刷新；不依赖 HAL/RTOS。
- `application/display_app.*` 读取里程计一致快照、格式化数字和状态，并调度刷新；注释使用中文。

100 kHz 下整帧纯线路时间约 100 ms，分块让出任务和被抢占还会延长刷新，因此默认使用 500 ms 周期。每个小块后阻塞一个 tick，给同级串口和其他低优先级工作让出执行机会。可以观察最大刷新耗时后再调整周期。

I2C3 目前由显示任务独占，后续若添加其他 I2C3 器件，需要统一总线访问。驱动不新增中断回调、DMA 通道或监测任务。只在启动/断线后检查 `0x3C/0x3D` 两个常用地址；也可以将 `DISPLAY_ADDRESS_7BIT` 设为固定 7 位地址。HAL 所需左移操作在 BSP 内部完成，配置处不要填写 `0x78/0x7A`。

## 上板查看

本次 Debug 编译通过，尚未烧录或进行屏幕实测。重新编译烧录后保持底盘静止，等待 IMU 标定和里程计建立原点，正常画面应为 `ODOM RUN E0`。

| `g_display` 字段 | 含义 |
| --- | --- |
| `ready / error` | 正常为 1/0；error=1 任务创建失败、2 I2C 配置不支持、3 无地址应答、4 传输失败 |
| `address_7bit` | 连接成功后为 0x3C 或 0x3D（十进制 60/61），或配置的固定地址 |
| `frames` | 完整刷新的帧数，持续增加 |
| `pose_valid` | 最近一次显示快照是否有效；它与屏幕通信 ready 独立 |
| `sample_timestamp_us` | 显示快照对应的里程计端点时间 |
| `io_errors / last_i2c_error` | 初始化/刷新失败次数与最近 HAL I2C 错误 |
| `max_refresh_ms` | 启用后的最大整帧刷新耗时，包含让出 CPU 和被抢占时间 |

屏幕缺失或传输失败时，每秒尝试重连；不停止 IMU、编码器、里程计或串口。地址应答且帧数增加但画面异常时，先核对控制芯片、分辨率与模块供电，而不是据此判断定位解算故障。
